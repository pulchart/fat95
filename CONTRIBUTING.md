# Contributing to fat95

fat95 is a FAT12/FAT16/FAT32 filesystem handler for AmigaOS, written in 68000 assembly in vasm Motorola syntax. It builds and is tested on Linux; an Amiga is needed only to try the result on real hardware.

## Build

You need vasm 2.0f with the Motorola syntax module and the m68k backend, built from <http://sun.hasenbraten.de/vasm/> with `make CPU=m68k SYNTAX=mot` and installed so that `/opt/vasm/bin/vasmm68k_mot` exists. Any other prefix works with `make VASM_HOME=/your/prefix`, and `make check-vasm` tells you whether the one it found is the expected version.

```sh
git submodule update --init      # extern/ptable, the bundled ptable.library
make                             # fat95, all CPU tiers, and the tools
make help                        # every target, with the output files
make V=1                         # show the full assembler command lines
```

`make ptable-bundle` stages `ptable.library` and `lsptres` from the `extern/ptable` submodule. To build guides, obtain the [md2guide.py converter](https://github.com/pulchart/cfd/blob/master/tools/md2guide.py) from the cfd repository and run `make guide MD2GUIDE=/path/to/md2guide.py`.

## Test

```sh
make test                        # all fast checks, 68000 and 68020 tiers
```

The emulator has no 68080 instructions, so `make test` does not run the 68080 tier; `make` builds it.

See [test setup and usage](tests/README.md) and the [coverage inventory](tests/INVENTORY.md).

Include tests with code changes. Describe each test in its docstring and refresh the inventory with `make test-list-update`.

## Sources

`src/fat95.s` is the whole handler. The 68000, 68020+ and Apollo 68080 tiers come from that one file through the `UMUL32`, `UDIVMOD32`, `LOG2`, `EXTBL` and `ZCLR*` macros defined at its top; new divergence between the tiers uses those macros or adds one in the same `ifd __68020__` shape. The 68080 tier sets both `__68020__` and `__68080__`; its own path is `perm` in `ReverseL`. `make APOLLOON=1` adds LineA opcodes, off by default because they fault on an IceDrake V4. The `src/*_version.i` files are generated by the Makefile, so do not edit them by hand. Keep sources ASCII-only.

## Commits

Do not stage `dist/`. The compiled binaries there are committed separately, in their own update commit, so a code change stays readable. `docs/changes.md` records what changed for a user of the release, so an internal change does not belong in it.
